# Сетевой режим 0.3

Проверено на Godot 4.7.2 и установленном Photon Fusion Godot SDK 3.0.0.2787.

## Исправления

- У чужого бойца отключены камера, ввод и руки первого лица; отображаются
  полноценная модель и отдельное оружие. Смена оружия скрывает старую модель сразу.
- Конфигурация репликации хранится в `scenes/player_replication.tres` и доступна
  SDK до спавна. Повороты из сети больше не перезаписываются локальным вводом.
- Значение seed ограничено положительным int32: иначе Photon мог менять его
  знак, а клиенты строили разные здания. Раскладка оружия тоже детерминирована.
- В момент локального спавна ID берётся из Fusion, поскольку owner_id
  репликатора может ещё быть нулём. Стартовые позиции учитывают ID и занятость.
- Урон передаёт бронепробитие и номер жизни цели; отправитель определяется
  транспортом. Подтверждённый фраг начисляется один раз, вместе с наградой.
- У мёртвого игрока отключены ввод и хитбокс; после респавна возвращаются
  здоровье, оружие, патроны и коллизия. Эти состояния видны другим клиентам.
- Подбор оружия проверяет текущий хост. Доступность точки общая, а время
  восстановления сохраняется в свойствах комнаты и переживает уход хоста.
- Поздний вход получает текущий матч. Выход удаляет своего бойца и спавнер,
  повторное подключение не вызывает повторную инициализацию SDK.
- Tab показывает участников, фраги и смерти. Esc в сети блокирует только
  локальный ввод, оставляя сетевую симуляцию работающей. Окно заполняется
  изображением при изменении пропорций без больших чёрных полос.

## Проверка

`tools/run_network_tests.ps1` запускает два отдельных процесса и создаёт
уникальную комнату. Ошибка проверки завершает прогон с ошибкой. Флаг
`-Capture` дополнительно сохраняет кадр отрисованного сетевого клиента.
Прогон требует установленного SDK, `photon.cfg` и доступа к Photon.

В этой версии SDK при завершении headless-процесса остаётся собственное
сообщение `Capture not registered: 'fusion'`. Тест отдельно проверяет итог
обоих клиентов и отсутствие ошибок GDScript; сообщение очистки SDK не
считается сбоем игровой логики.

## Границы реализации

Это Shared Authority для игры с друзьями: клиент рассчитывает попадание,
владелец цели применяет урон. Выделенного сервера, защиты от изменённого
клиента и серверной компенсации задержки здесь нет. Проверки выполнялись
двумя процессами на одной машине через облако; мобильные сети и высокая
потеря пакетов отдельно не испытывались.

Конфигурация свойств и маршрутизация RPC сверены с документацией
[репликации Photon](https://doc.photonengine.com/fusion-godot/v3-shared-authority/manual/replication/syncing-properties)
и [RPC Photon](https://doc.photonengine.com/fusion-godot/v3-shared-authority/manual/rpcs/basics).
