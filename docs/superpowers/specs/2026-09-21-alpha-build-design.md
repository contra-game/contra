# Альфа-билд: руки, меню с лобби, сетевой боец, экспорт .exe

Дата: 2026-09-21
Статус: одобрено

## Задача

Собрать альфа-версию Contra City как `.exe`, в которую двое заходят по сети через
Photon и видят друг друга. Требуется четыре куска работы: руки от первого лица
вместо примитивов, главное меню с лобби, модель бойца вместо капсулы у сетевого
игрока и сборка билда с вшитым App ID.

## Принятые решения

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Руки | Вырезать из `characterMedium.fbx` по весам костей | Ассет уже в репозитории, CC0, стиль совпадает с ботами и городом |
| Меню | Меню + лобби со списком игроков | Видно, кто зашёл; матч стартует по кнопке хоста, а не по факту входа |
| Билд | Debug с консолью, zip | На альфе важнее видеть причину сбоя, чем пару кадров fps |
| Боты в сети | Остаются локальными у каждого клиента | Карта живая; расхождение фрагов по ботам принято сознательно |

## Факты, на которых стоит дизайн

Проверены в этом проекте, не взяты из документации.

**Fusion API** (выгружено через `ClassDB` на установленном SDK 3.0.0 Build 555):

- `Fusion.rpc(method: Callable) -> FusionRpcResult` — широковещательный вызов
- `Fusion.rpc_to_player(player_id: int, method: Callable)` — адресный
- `Fusion.register_broadcast_receiver(node: Node)` — узел принимает broadcast
- `Fusion.is_master_client() -> bool`, `Fusion.get_local_player_id() -> int`
- `Fusion.get_rpc_sender() -> int` — кто прислал текущий RPC
- `FusionRoom.get_players() -> Array` из `FusionPlayer`
- `FusionPlayer`: `get_user_id()`, `get_number()`, `get_is_master_client()`, `get_is_inactive()`
- Сигналы `Fusion`: `room_joined`, `room_left`, `player_joined(id, user_id)`,
  `player_left(id, is_inactive)`, `master_client_changed`, `connected_to_photon`,
  `connection_failed`, `connection_status_changed`

**Модель бойца** `assets/characters/Model/characterMedium.fbx`:

- Иерархия: `characterMedium` → `Root` → `Skeleton3D` → `characterMedium` (MeshInstance3D)
- Один меш, одна поверхность — отдельных объектов головы, рук и ног нет
- 58 костей, включая пальцы: `RightHand`, `RightHandIndex1..3`, `RightHandThumb1..2`
  и зеркальные левые; руки крепятся через `LeftShoulder` / `RightShoulder`

**Текущее состояние кода**, которое меняется:

- `scenes/main.tscn` — стартовая сцена, сразу строит карту и лезет в сеть
- `scripts/game.gd` — сам создаёт `NetManager`, тот умирает вместе с матчем
- `scripts/net_manager.gd:20` — имя комнаты зашито как `contra-city`
- `scripts/game.gd:25` — seed матча зашит константой `match_seed`
- `scripts/view_model.gd::attach_hands` — руки из капсулы и коробки
- `scenes/player.tscn:26` — тело игрока `CapsuleMesh`, видимое только чужим

## Архитектура

### Сессия переживает смену сцен

Появляется autoload `Session` (`scripts/session.gd`). Он держит имя игрока, имя
комнаты, подключение к Photon и состояние лобби — всё, что должно жить дольше
одной сцены. `NetManager` переезжает под него; `game.gd` больше не поднимает сеть
сам, а берёт готовую `Session.net`.

Поток сцен:

```
menu.tscn  --«Играть по сети»-->  lobby.tscn  --RPC старта-->  main.tscn
    |                                                              |
    \--«Офлайн с ботами»------------------------------------------/
                     main.tscn  --Esc → «Выйти в меню»-->  menu.tscn
```

Интерфейс `Session` для остальных сцен:

- `player_name: String`, `room_name: String` — что ввели в меню
- `connect_and_join()` — подключиться и войти в комнату, вернуть успех
- `leave()` — выйти из комнаты, остаться подключённым
- `players() -> Array` — список для лобби: имя, id, хост ли
- `start_match(seed)` — только у мастера: разослать старт и перейти в матч
- сигналы: `lobby_changed`, `match_started(seed)`, `state_text(text)`

### Меню

`scenes/menu.tscn` становится главной сценой проекта. Поля: имя игрока, имя
комнаты. Кнопки: «Играть по сети», «Офлайн с ботами», «Настройки», «Выход».
Имя и комната сохраняются в `user://settings.cfg` и подставляются при следующем
запуске. Статус подключения выводится строкой внизу, а не в киллфид.

Имя игрока уезжает в Photon как `user_id` вида `Владос#4821` — четыре случайные
цифры дают уникальность, при показе хвост обрезается. Так имя приходит всем через
`FusionPlayer.get_user_id()`, и отдельный обмен именами по RPC не нужен.

### Лобби

`scenes/lobby.tscn` показывает список из `room.get_players()`: имя, пометка хоста.
Список обновляется по `player_joined`, `player_left`, `master_client_changed`.
Кнопка «Начать матч» доступна только мастеру (`Fusion.is_master_client()`),
остальные видят «Ждём хоста». Кнопка «Выйти из комнаты» возвращает в меню.

Старт: мастер шлёт `Fusion.rpc(Callable(session, "_remote_start").bind(seed))`,
где seed — случайное число. Все клиенты, включая отправителя, переходят в
`main.tscn` с этим seed, поэтому карта у всех одна. Готовности игроков нет — хост
видит состав и стартует сам.

### Руки

`scripts/first_person_arms.gd` строит меш рук один раз при загрузке:

1. Инстанцирует `characterMedium.fbx`, берёт единственный `MeshInstance3D`.
2. Читает `surface_get_arrays()`, смотрит массивы `ARRAY_BONES` и `ARRAY_WEIGHTS`.
3. Оставляет вершины, у которых суммарный вес на костях рук выше 0.5. Кости рук —
   те, чьи имена начинаются на `LeftShoulder`, `LeftArm`, `LeftForeArm`, `LeftHand`,
   и зеркальные правые.
4. Собирает новый `ArrayMesh` из отобранных вершин с перенумерованными индексами.

Руки живут в держателе оружия — там же, где сейчас примитивы. Значит отдача,
перезарядка и покачивание работают без изменений: они двигают держатель, а руки
едут вместе с ним. Кисти ставятся на точки хвата поворотом костей `RightHand` и
`LeftHand`.

Если фильтрация даст рваные края на плечах, запасной путь — оставить меш целиком и
схлопнуть лишние кости через `Skeleton3D.set_bone_pose_scale(idx, Vector3.ZERO)`
для `Head`, `LeftUpLeg`, `RightUpLeg`. Тогда голова и ноги стягиваются в точку.

`ViewModel.attach_hands` с капсулами удаляется.

### Сетевой боец

`CapsuleMesh` в `scenes/player.tscn` заменяется на модель, которую собирает
существующий `scripts/character_model.gd` — тот же код, что уже работает для ботов.
Логика видимости не меняется: `visible = not local_control`, свой игрок своё тело
не видит. Анимации idle и run переключаются по горизонтальной скорости, как у
ботов.

## Сборка

1. Скачать шаблоны экспорта Godot 4.7.2 — 1 281 349 702 байта с GitHub-релиза,
   проверить SHA-512 по `SHA512-SUMS.txt` релиза.
2. Создать `export_presets.cfg`: пресет Windows Desktop, `export_debug=true`,
   консоль включена.
3. В `include_filter` добавить `photon.cfg` — иначе App ID не попадёт в PCK и билд
   уйдёт в офлайн.
4. Экспортировать в `build/`. Godot кладёт рядом с exe
   `libfusion.windows.template_debug.x86_64.release.dll` — нативная библиотека не
   упаковывается внутрь PCK, поэтому билд это папка, а не один файл.
5. Собрать `build/contra-alpha-debug.zip`: exe, pck, dll, короткий readme о том,
   как запускать и что вводить в меню.

`build/` и `export_presets.cfg` (в нём пути с конкретной машины) добавляются в
`.gitignore`.

## Риски

- **SDK в статусе preview.** Photon прямо пишет, что Fusion Godot SDK 3.0 не для
  продакшена и API может меняться. Для альфы на двоих это приемлемо.
- **Фраги по ботам разойдутся.** Следствие решения оставить ботов локальными:
  каждый бьёт своих ботов, счёт по ним у игроков разный. Фраги по живому игроку
  считаются честно — урон идёт через RPC владельцу цели.
- **Godot 4.6.3 перебивает импорт.** Пока открыт редактор 4.6.3, он переписывает
  `*.import` под формат 4.6 и понижает `config/features`. Работать только в 4.7.2.
- **App ID уезжает в билд.** Любой, кто вскроет PCK, получит App ID и сможет жечь
  лимиты аккаунта. Для альфы на двоих принято; для публичной раздачи понадобится
  прокси или отдельный App ID.
